# Android Run一覧の入口

AndroidアプリはRunの実行・修正、Widget設定を担当し、再利用する段取りの探索・整理はWebに寄せる。主画面の中心は常にRun一覧とし、`表示`・`再利用`・`アーカイブ`のトップレベル切替は置かない。

## 固定した画面仕様

| 状態 | ヘッダー | 本文 |
| --- | --- | --- |
| 実行中Runあり | アカウント／Webで探す／新規作成／Widget設定（アイコンのみ） | 実行中Runをすべて表示 |
| 実行中Runなし | アカウント／新規作成／Widget設定（アイコンのみ） | `Webでタスクを探す ↗`を中央の主導線として表示 |
| 完了Runあり | 上記と同じ | 実行中Runの後に、最新の完了Runを1件だけ表示。その下に`完了履歴からもう一度使う ↗` |

- 完了履歴リンクはWebの`?view=history`を開く。Android内に履歴一覧やPrivate Cuebook編集画面を作らない。
- 新規作成はヘッダーの＋から名前入力ダイアログを開く。常設テキスト入力は置かない。
- Widget設定はヘッダーのWidgetアイコンから既存の設定sheetを開く。
- 完了Runのカード自体はローカル詳細を開く。過去の内容確認とUndoはAndroid内で完結する。
- Web RevisionのImportはAndroidのCuebookを作らず、日付を展開したRunへ直接取り込む。
- 既存RoomのCuebookテーブルはデータ互換のため直ちには削除しないが、画面・Importからは利用しない。

## 検証

実際の`RunListScreen`とin-memory Roomを使い、空・完了のみ・実行中の3状態を計装テストで固定する。アクセシビリティ上、アイコン操作は日本語のcontent descriptionで特定できる。画面テスト用データは利用者のRoomへ保存しない。

この構成は、`frontend-ui-engineering`の「主操作を状態に応じて一つに絞る」「アイコンにも名称を与える」という観点を適用した。
