# Verification artifact policy

Screenshots and raw verification outputs are local working material, not source assets. Keep `docs/review-screenshots/` and `output/` ignored and untracked. Never force-add either directory. Historical document links into these directories refer to local evidence and are no longer expected to resolve on GitHub.

Commit concise test scope, outcomes and limitations instead. Do not commit full build/rollout responses, environment values, credentials, internal resource identifiers, personal data or raw service responses. Production application assets deliberately used by the product belong in its asset directories; they are distinct from review screenshots.

Android and iOS screenshot workflows have read-only repository permissions and do not commit or push generated files. Only test screenshots are uploaded as artifacts with 14-day retention. Public-repository artifacts are not a secret store: use synthetic test data, never production accounts or private content. Raw logs, UI dumps and test bundles are excluded from artifact uploads. Existing historical artifacts are not deleted by changing these workflows.

Some local verification scripts consume files generated by earlier preparation scripts. Generate those inputs locally before running dependent scripts; do not restore committed production exports to make a clean checkout pass.
